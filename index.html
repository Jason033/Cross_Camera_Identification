如何認出同一個人？

01 / THE PROBLEM

先看懂問題，才知道該找什麼

一般 ReID 很容易利用衣服顏色與款式。當每個人都穿迷彩服、帽子和相同鞋款，外觀會變得很相似，系統需要更多證據。

你的情境

不同人，同樣衣服

同制服 + 攝影機視角不同 + 人員可能是陌生人。目標是跨鏡頭找回同一人。

相關但不同

同一人，換了衣服

換衣 ReID 研究如何避開服裝變化，能借用方法，但測試設計與同制服問題不同。

真實挑戰

看不清、看不到、沒走路

畫面品質、遮擋與動作會讓某些線索失效；還要允許系統回答「待確認」。

攝影機畫面偵測與追蹤抽取多種線索比對資料庫候選人／未知
02 / IDENTITY CUES

人身上還有哪些線索？

點選線索，看它提供什麼，以及什麼情況會失效。

外觀：畫面裡還保留了什麼？

臉部輪廓、髮型、裝備細節與體型等可能有幫助。你現有的 FastReID 與 CLIP-ReID 就是這條路的起點。

注意：模型也可能過度依賴背景或服裝。衣服越相似，這些線索越難分辨。

骨架：關節與身體結構

把頭、肩、肘、髖、膝等關節位置串起來。可觀察肢體比例及一連串姿勢變化。

注意：遠距、遮擋或錯誤關節會破壞資訊；2D 比例也會隨視角改變。

步態：一段時間怎麼走

擺臂、抬腳、步幅與姿勢變化合起來形成動態線索。步態可以從骨架或輪廓序列抽取。

注意：通常需要足夠長、品質合適的連續畫面；站立、轉身或遮擋時會變弱。

輪廓：人物的外形剪影

先將人物從背景分出來，觀察整體外形和輪廓隨行走的變化。輪廓不直接使用衣服顏色。

注意：寬鬆衣物、背包和分割錯誤會改變剪影。

臉部：清楚時是重要補充

正面、解析度夠且沒有明顯遮擋時，臉部可以提供額外身分資訊。

注意：監視器經常拍到背面或側面，不能假定每段畫面都有可用的臉。

時間與空間：幫助篩選候選

如果已知攝影機位置和時間，可檢查兩次出現之間的移動是否合理。

注意：這是輔助條件，不是身分本身；時間不同步、繞路或路徑未知可能造成誤判。

比例與體型可以研究，但 2D 攝影機的高度、距離和角度都會改變外觀；不要直接把像素高度當成真實身高。

01 / SCORE FUSION

分數融合

各模型各自比對，再合併分數。容易做為第一個多模態基準；不同模型分數尺度要校準。

02 / FEATURE FUSION

特徵融合

先整合各分支的特徵，再交給模型學習。需要考慮特徵尺度、對齊與訓練資料。

03 / QUALITY-AWARE

依品質動態調整

例如人臉不可見時降低人臉權重；骨架品質差時降低骨架權重。效果仍需實驗證明。

影像／軌跡外觀、骨架、輪廓品質評估融合或跳過缺失分支候選／待確認
06 / YOUR NEXT STEPS

從現有系統出發，逐步驗證

這是建議的研究順序；每加一個分支，都要能回答它改善了哪些錯誤。

01 · BASELINE

先量出現在的表現

YOLOv7 偵測 → 追蹤 → FastReID／CLIP-ReID。固定資料切分，記錄跨視角候選排序。

02 · HARD CASES

整理同制服難例

比較同一人跨角度、不同人同制服，記錄低解析、背面與遮擋造成的錯配。

03 · ONE BRANCH

只加入一條新線索

先試骨架步態或輪廓步態之一；比較單分支與外觀分支的錯誤是否互補。

04 · FUSION

從簡單融合開始

先做分數融合，再與動態權重比較。用缺失、遮擋與低畫質條件檢查穩定性。

05 · UNKNOWN

讓系統有拒判選項

以獨立驗證資料校準門檻；測試資料庫沒有該人時，能否輸出未知或待確認。

06 · TRANSFER

換場景再測一次

測不同鏡頭角度與資料來源；目前單攝影機多角度先驗證視角變化，多攝影機效果仍需另外驗證。

Rank-1 / mAP候選排序與整體檢索
錯配案例看具體錯在哪裡
FAR / FRR未知人錯認與已知人拒判
FPS / 延遲模型運算與等待成本
GPGait、OpenGait 等套件的 Python、PyTorch、CUDA 相容性需要逐一核對；目前的 Python 3.9 / PyTorch 1.11 環境不保證能直接安裝。
