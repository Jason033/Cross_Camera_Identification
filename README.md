# 同制服跨攝影機辨識｜技術探索地圖

高度相似制服環境下的跨攝影機人員再辨識（Cross-Camera Person Re-Identification）第一階段文獻研究，整理成以圖表與互動為主的網頁。

## 怎麼開

**線上：** 若已開啟 GitHub Pages，網址為 `https://jason033.github.io/Cross_Camera_Identification/`。

**離線（任何電腦）：**
1. 在 GitHub 頁面按 **Code → Download ZIP**
2. 解壓縮（保持資料夾結構，`index.html` 要和 `assets/` 在同一層）
3. 直接雙擊 `index.html`，用 Chrome / Edge / Firefox 開啟即可

不需要安裝任何東西、不需要網路、不需要架伺服器。網站不載入任何線上字型、程式庫或圖片；只有「參考文獻」裡的論文連結需要網路。

## 內容

**專案目標**：國軍版的「天眼」——利用營區既有的一般光學監視器，自動重建「誰、在什麼時間、經過哪些地點」。用途：重建每人移動路徑、事後查詢特定人員、標出名冊外的人。

**第一階段範圍**：同一畫面 5 人以內（不含部隊行進）；白天與一般照明（夜間、雨天看不清時允許「無法判定」）；迷彩服＋小帽、鋼盔、夏季捲袖、冬季外套、運動服，**同一天內會換裝**；攝影機配置未知，以常見路邊監視器為參考；門禁刷卡只當輔助證據（可能被代刷）。

文件的主幹依系統的七個步驟（外加 Q：查詢輸出）組織：攝影機與偵測 → 追蹤成片段 → 身分線索特徵 → 換成證據（融合）→ 時空約束 → 分群 → 比對名冊（刷卡輔助）。每一步依序是：路線地圖（這一步有哪幾種做法與取捨）→ 主要方法（怎麼運作：輸入、處理、訓練、輸出；在路邊俯角、換裝、5 人交錯、CPU 算力、軍用授權下的優缺點）→ 其他方法 → 我們的選擇（單一選擇、起始設定、通過條件）。各方法的程式碼、權重、輸入格式與第一步怎麼試收在可展開的「實作資訊」裡。讀者設定為剛接觸這個領域的工程師：文中第一次出現的專有名詞有虛線底線，滑過即可看解釋。

## 閱讀須知

- 圖中人物、特徵點、分數分布都是**程式產生的教學示意**，不是實驗結果。服裝依國軍常見樣式繪製，配色為近似值。
- 每個主張都標了證據等級：■ 文獻證實　◧ 合理推論　⬚ 待驗證。
- 2026 年的資料集（Industrial-Gait、ConstrID、FG-PersonX、MMGait）皆已確認存在；標「部分待核對」者，部分數字取自前次研究報告。
- 授權欄位是研究時讀到的狀態，正式採用前請法務確認。

## 檔案結構

```
index.html            所有章節的文字與版面
assets/style.css      樣式
assets/js/pipeline.js 單一資料來源（PIPE）：章節順序與章號、我們的 ①–⑦＋Q、系統層 9 步、方法層槽位、基準、按鈕、注意事項、交叉引用 token（{{ch:…}}、{{step:…}}、{{count:…}}）；改章節順序、步驟名稱、數量只改這裡
assets/js/slots.js    方法槽位資料（SLOTDATA）：每張主要方法卡在各槽位的做法，以及與本組基準不同的槽位（diff）
assets/js/pipeview.js 把 PIPE 畫成圖：主圖、系統步驟尺、步驟條、組合條、迷你地圖、槽位表、部署架構、每日時程、決策流程、身分狀態圖；也負責三種按鈕與圖例

assets/js/steps.js    方法總覽的內容：七步的候選方法、判定與實作資訊（改內容主要改這裡）
assets/js/ch-steps.js 依 steps.js 產生方法卡片、第一版元件表與總覽摘要
assets/js/others.js   別人怎麼做的內容：架構類型與各系統的流程、系統層對應（sys）、可借用與不適合之處（改內容主要改這裡）
assets/js/ch-others.js 依 others.js 產生架構卡、對照表與系統卡片
assets/js/flowplay.js 「▶ 動畫」播放器：共通步驟用共用場景快速帶過；各系統的特色步驟（x_ 場景）放慢說明；sys_line 場景畫出系統在 9 欄系統層上的位置

assets/js/ourplay.js  我們的做法的動畫：第一版系統從頭到尾、七步各自的細部設定、身分四層、交付成果（場景數字與 steps.js 的起始設定一致）

assets/js/research.js 第二輪研究：方法總表、證據卡、系統、驗證、品控資料
assets/js/geom.js     攝影機幾何（可行性計算器）
```

### 檢查工具

改完內容或程式後，在專案根目錄執行：

```
node tools/check.js
```

會檢查章節順序與章號、手寫章號或步號、各處數量（實驗、方法、系統、架構）、交叉引用、方法槽位資料、離線可用（只用相對路徑、不載入外部資源）、按鈕文字與圖例、注意事項重複次數、標題層級，並用 Playwright（需自行安裝，找不到時顯示 SKIP）逐章開啟、點開動畫視窗與按鈕確認沒有錯誤。最後一行 `SUMMARY: … 0 FAIL` 且結束碼為 0 才算通過。預設各類按鈕只抽樣測試；要全部點過一次：

```
CHECK_ALL=1 node tools/check.js
```

全部為原生 HTML / CSS / JavaScript，沒有建置步驟。更早的版本保留在 git 歷史中（例如 commit `477b93f`、`2562b2e`）。
